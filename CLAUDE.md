# CLAUDE.md - Project Configuration

## Project Overview
This is the `@peter.naydenov/dom-selector` library - a DOM selection and reference organizer.

## Testing Stack
- **Test Runner**: Vitest with the `jsdom` environment
- **Test Files**: `test/01-general.spec.js`, `test/02-bug-fixes.spec.js`
- **Test HTML**: `index.html` — `test/setup.js` loads its `#app` markup into `document.body` before each test

## Commands
```bash
npm test         # Run Vitest once
npm run test:ui  # Run tests with the Vitest UI
npm run cover    # Coverage report (v8)
npm run build    # Vite build to dist/, then tsc emits types/main.d.ts
```

## Key Files
- `src/main.js` - Main library source (JSDoc is the source of truth for the types)
- `types/main.d.ts` - Generated by `tsc` on `postbuild`; do not edit by hand
- `types/main.d.cts` - Hand-written CommonJS types (`export =`), re-uses the types from `main.d.ts`
- `dist/dom-selector.cjs` - CommonJS build; must keep the `.cjs` extension because the package is `"type": "module"`
- `index.html` - Test HTML fixture with DOM content

## Package Exports
- Every condition in `exports["."]` carries its own `types` entry — TypeScript ignores the top-level `"types"` field when `exports` is present.
- After changing `exports`, verify from a consumer: `npm pack`, install the tarball in a scratch project, type-check with `--moduleResolution node16`, `nodenext` and `bundler`, and run both `import` and `require()`.

## Test Conventions
- Import `test`, `expect` from `vitest`; group with `test.describe`
- Import the library directly: `import DomSelector from '../src/main.js'`
- Tests run against the jsdom `document`, no browser required
